# ROADMAP.md — стадии разработки (референс и контроль)

Правило: стадия закрыта только когда её «Критерий приёмки» выполнен **сырым выводом команды**
(тест/скрипт/замер), записанным в `docs/evidence/S<номер>/`. Не «сделано», а «проверено чем».
Порядок стадий обязателен: фронт закрывается полностью на моках, потом сервер, потом БД-инстанцией.

Легенда исполнителя: **О** — оркестратор (я), **В** — локальный воркер (сабагент на kat-coder).

---

## S0. Каркас репозитория  ·  статус: [ ]  ·  делает О

Задачи:
1. npm workspaces (`shared`, `frontend`, `backend`), корневой `package.json`, `.gitignore`, `.env.example`.
2. `git init`, первый коммит, ветка `main`.
3. `docs/` (этот план, архитектура, рулсет, ADR, статус, приёмка, runbook, evidence).
4. Каркас `shared`: `domain.ts`, `schemas.ts`, `constants.ts`, `ws-protocol.ts`, `money.ts`, `time.ts` — типы без реализации.
5. CI-минимум: скрипт `npm run check` = `typecheck + lint + test` по воркспейсам (без GitHub Actions, локально).

Критерий: `npm run typecheck` по всем воркспейсам — exit 0 (сырой вывод).

## S1. Доменный контракт  ·  статус: [ ]  ·  делает О + В

Задачи:
1. `docs/DOMAIN.md` — статусы и переходы, тарифы, пороги, зона, тайминги (референс для всех).
2. `shared`: zod-схемы запросов/ответов, ws-протокол с `seq`/`sent_at`, `server_time` в каждом ответе.
3. `shared/src/money.ts` — минорные единицы, формат `6.50 сом`, без `float`.
4. `shared/src/time.ts` — `Clock` (инъекция), `splitRideSegments`, `billableMinutes` (округление вверх).
5. `shared/src/zone.ts` — ray casting по полигону зоны + расстояние до границы.
6. Тесты `shared` (vitest): деньги, минуты, сегменты пауз, зона, формат.

Критерий: `npm test -w shared` — все зелёные, счёт assertion'ов в выводе; таблица цен из `DOMAIN.md`
проверена тестом дословно.

## S2. Мок-данные  ·  статус: [ ]  ·  делает В (локальная модель) + О (проверка)

Задачи:
1. Воркер генерирует `mock/*.json`: 40 самокатов в центре Бишкека (код, модель, статус, заряд, координаты),
   6 пользователей, 25 завершённых поездок с корректным `breakdown`, счета к ним, письма.
2. Схема JSON = zod-схемы из `shared` (валидация файла тестом).
3. Сид детерминированный (фиксированный seed) — повторная генерация даёт тот же файл.

Критерий: тест `shared/tests/mock.test.ts` валидирует все `mock/*.json` схемами и проверяет,
что 40 самокатов внутри полигона зоны, >25 % имеют заряд ниже порога (для проверки B9),
суммы в счетах совпадают с пересчётом `calcRidePrice`.

## S3. Карта парка  ·  статус: [ ]  ·  делает В + О (визуальная приёмка)

Задачи:
1. Vite+React+TS каркас, Tailwind 4 (`@theme` токены в `global.css`), shadcn/ui базис.
2. Leaflet + react-leaflet, подложка ArcGIS Light Gray Canvas (без ключа), полигон зоны обслуживания.
3. Маркеры парка с цветом по статусу, кластеризация не нужна, попап с зарядом и кодом.
4. Легенда статусов, панель фильтров (только свободные / все), счётчик парка.
5. `ApiClient` интерфейс + `MockApiClient` (фетч `mock/*.json`, имитация задержки 120–300 мс),
   переключение mock/http через `VITE_API_MODE`.

Критерий: не «элементы есть», а замер: 40 маркеров в DOM, полигон в DOM, статусы совпадают с JSON,
нет перекрытия элементов в шапке (пересечение 0 px), скриншот + вердикт по внешнему виду.

## S4. Бронь и таймер 15 минут  ·  статус: [ ]  ·  делает В + О

Задачи:
1. Бронь через `ApiClient.createBooking` → мок-реализация соблюдает правило «один активный» (`409`).
2. Панель активной брони: обратный отсчёт от `server_time`, а не от `Date.now()`.
3. Уведомление за 3 минуты (тост + запись в список писем).
4. Автоснятие по истечении в мок-симуляторе, самокат снова свободен.

Критерий: тесты `@testing-library/react` на таймер (инъекция часов: 15:00 → 3:00 → 0:00),
мок-гонка двух бронирований в одном тесте → второй получает `409`; e2e ещё нет, проверяем юнит + браузер.

## S5. Поездка  ·  статус: [ ]  ·  делает В + О

Задачи:
1. Старт поездки из брони, пауза/возобновление, завершение (кнопка) — всё через `ApiClient`.
2. Живой счётчик: время, минуты по тарифу езды и паузы, текущая сумма (минорные единицы).
3. Запрет завершения вне зоны: кнопка с пояснением, серверная (мок) проверка → `422 outside_zone`.
4. Потеря связи (мок: oфлайн-флаг): поездка продолжается, при возврате — resync снапшота и «догон» счёта.
5. Автофиниш при заряде 0 % (мок-симулятор), письмо с пояснением.

Критерий: юнит-тесты на расчёт цены в реальном времени, e2e-сценарий на одном клиенте,
замер в браузере: сумма в панели = `calcRidePrice` на ту же длительность (расхождение 0).

## S6. Кабинет и почта  ·  статус: [ ]  ·  делает В + О

Задачи: текущая поездка, история поездок с пагинацией, список счетов с breakdown,
экран «Входящие» (эмуляция почты), профиль. Роутер: `/map`, `/account`, `/rides`, `/invoices`, `/inbox`, `/login`.

Критерий: тесты компонентов + скриншоты; проверка, что на 25 завершённых поездок ровно 25 писем
(дедупликация) и суммы в счёте сходятся с breakdown.

## S7. Закрытие фронта  ·  статус: [ ]  ·  делает О

Задачи: прогон всех тестов фронта, Playwright e2e (два контекста), фиксация evidence, `docs/STATUS.md`
со честным «что работает на моках», тег `frontend-closed`.

Критерий: полный прогон (`vitest` + `playwright`) с нулём падений, сырые выводы в `docs/evidence/S7/`.

## S8. Бэкенд: каркас, БД, миграции  ·  статус: [ ]  ·  делает О + В

Задачи:
1. Fastify: `server.ts`, плагины (`cors` не нужен внутри nginx-сети, но оставим для dev), pino-логи, graceful shutdown.
2. `pg.Pool` + транзакционный хелпер; свой раннер SQL-миграций (`schema_migrations`, каждая в транзакции).
3. Миграции: таблицы из `ARCHITECTURE.md §5`, триггер `set_updated_at`, частичные уникальные индексы, CHECK-и.
4. Сид из `mock/*.json` (идемпотентный, `ON CONFLICT DO NOTHING`).
5. `GET /api/health` + `server_time`.

Критерий: `docker compose up -d db` → `npm run migrate && npm run seed -w backend` → тест на инварианты БД
(второй активный бронь/заезд невозможен, `updated_at` меняется триггером) — сырой вывод.

## S9. Бэкенд: REST + WS + симулятор  ·  статус: [ ]  ·  делает О + В

Задачи: все ручки из `ARCHITECTURE.md §6`; ws-хаб с broadcast, снапшот, `seq`, heartbeat;
серверный симулятор парка (тик 1 с); тик брони (5 с); auth (register/login/refresh/logout, JWT + refresh-cookie).

Критерий: интеграционные тесты `app.inject` на каждую ручку (коды 200/201/400/401/409/422),
тест WS: два сокета получают один и тот же `park.delta`; тест «два одновременных POST /bookings → один 201, один 409».

## S10. Бэкенд: тарификация, счета, письма  ·  статус: [ ]  ·  делает О + В

Задачи: `calcRidePrice` на сервере (та же функция из `shared`), финализация счёта, `invoices`, письма
с `dedupe_key`, автофиниш по заряду и по концу зоны, пауза/резюм с корректными интервалами.

Критерий: тест «поездка 15 мин + пауза 4 мин 20 с» = цена из `DOMAIN.md`; тест «финиш дважды» → один счёт
и одно письмо; тест на 0 потерь: `sum(invoices.amount)` = `sum(breakdown.total)` по 100 случайным поездкам.

## S11. Переключение фронта на реальный API  ·  статус: [ ]  ·  делает О

Задачи: `VITE_API_MODE=http`, http-реализация `ApiClient` + `useParkStream` на ws, включение
реальной реконнект-логики, снятие фронтового симулятора (остаётся в коде как dev-инструмент).

Критерий: e2e на двух клиентах по реальному стеку: бронь у одного → второй видит `booked` за < 500 мс;
второй получает `409`; автоснятие брони через 15 мин (тест с подменой времени на сервере);
потеря связи (обрыв ws) → resync без расхождений в счёте.

## S12. Докер, документация, сдача  ·  статус: [ ]  ·  делает О

Задачи:
1. `docker-compose.yml` (3 сервиса, healthcheck, depends_on, том, проксирование /api и /ws через nginx).
2. Прогон на «чистой» машине: `docker compose up --build` → фронт на `localhost:8088`, БД сидирована.
3. `README.md`, `RUNBOOK.md`, `STATUS.md` (честная таблица: работает / не работает / не делали и почему),
   `ACCEPTANCE.md` (пункт ТЗ → команда → сырой вывод), `DECISIONS.md`, `AI_USAGE.md`, `prompts/`.
4. Скрипт `scripts/demo.sh` — воспроизводимый сценарий двух клиентов для приёмки (или Playwright-видео).

Критерий: с нуля `git clone` → `docker compose up --build` → e2e-прогон зелёный. Все пункты B1–B9
имеют строку в `ACCEPTANCE.md` с сырым выводом в `docs/evidence/S12/`.
