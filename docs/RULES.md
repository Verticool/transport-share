# RULES.md — рулсет проекта (границы, не обсуждаются без явного решения)

Рулсет — это баундарис из ТЗ плюс наши собственные инженерные ограничения. Нарушение пункта
рулсета = баг. Изменение рулсета = запись в `docs/DECISIONS.md` с причиной.

## A. Из ТЗ (жёсткие требования заказчика)

| # | Требование | Как выполняем |
|---|---|---|
| A1 | Клиент-серверный продукт: отдельный backend и отдельный frontend, общение по сети | 3 контейнера: `frontend` (nginx+статика), `backend` (Fastify), `db` (Postgres). Фронт общается с бэком только по HTTP/WS |
| A2 | Backend: Python/Go/Node.js (предпочтительно) | Node.js 22 LTS + TypeScript. Обоснование — `docs/ARCHITECTURE.md §2` |
| A3 | Frontend: Vue или React | React 19 + Vite 8 + TypeScript |
| A4 | Хранилище: реляционная СУБД, предпочтительно PostgreSQL | PostgreSQL 17 (контейнер), доступ через `pg`, без ORM |
| A5 | Учётные записи: на наше усмотрение | Логин по email + пароль (bcryptjs), сессия на JWT (access в memory + refresh в httpOnly cookie). Без регистрации смотреть карту можно — бронь требует входа |
| A6 | Промпты / лог решений сдаются вместе с кодом | `docs/DECISIONS.md` (ADR по каждому выбору), `docs/AI_USAGE.md` + `prompts/` (сырые задания сабагентам) |
| A7 | Использование AI-агентов ожидается, скрывать не нужно | Прямо описано в `docs/AI_USAGE.md`: какая модель, какие задачи, где оркестратор, где локальный воркер |
| A8 | Предварительные требования для развёртывания описаны | `docs/RUNBOOK.md` + `README.md`, проверены на чистой машине |
| A9 | Локальный запуск, быстро разворачивается | `docker compose up --build` — один шаг; альтернативный «dev-режим без докера» тоже описан |
| A10 | Внешние сервисы эмулируются | Почта — таблица `emails` + веб-просмотрщик «Входящие»; внешних API нет вообще |
| A11 | Работает при двух одновременно открытых клиентах | WebSocket-хаб: состояние парка пушится всем сокетам; второй клиент видит статус сразу |

## B. Поведенческие требования продукта (приёмка по ним)

| # | Требование | Где реализуется |
|---|---|---|
| B1 | Состояние транспорта на карте меняется у всех сразу | WS-хаб → broadcast `park.state` |
| B2 | Один транспорт не могут забронировать двое, даже одновременно | Атомарный `UPDATE ... WHERE status='free' RETURNING` + частичный уникальный индекс на активную бронь |
| B3 | Бронь без старта за 15 мин снимается сама; за 3 мин до снятия уведомление | Серверный таймер брони (`setInterval`), событие `booking.expiring` + письмо, затем `booking.expired` |
| B4 | Счёт по минутам от старта до завершения, пауза по своему тарифу, копейки не теряются | Целочисленная арифметика в минорных единицах (тыйын), поминутное округление вверх по сегментам, breakdown в счёте |
| B5 | Завершить поездку вне зоны обслуживания нельзя, граница видна | Полигон зоны на карте + серверная проверка `ST_Contains`-эквивалентом (ray casting в коде, без PostGIS) |
| B6 | Заряд кончился в поездке → завершение автоматически + письмо со счётом и пояснением | Симулятор пишет заряд; при ≤0 — авто-финиш с `end_reason='battery_depleted'` |
| B7 | Пропала связь в поездке → поездка и счёт продолжаются, при возврате актуальное состояние | Поездка живёт на сервере; клиент при реконнекте делает полный resync (снапшот + `server_time` + `seq`) |
| B8 | По завершении приходит ровно одно письмо со счётом | Идемпотентность: `UNIQUE(invoices.ride_id)`, `UNIQUE(emails.dedupe_key)` |
| B9 | Транспорт с низким зарядом не показывается свободным | Порог заряда в конфиге; ниже порога самокат уходит в `unavailable` |

## C. Инженерные ограничения проекта (наши)

| # | Правило | Причина |
|---|---|---|
| C1 | Никакого Redis, Prisma, GraphQL, очередей, k8s, микросервисов | Проект локальный, стадиальный; лишний рантайм = лишние точки отказа |
| C2 | Модули выбираются по принципу «нужен для требования» | Каждая зависимость в `docs/DECISIONS.md` с причиной и альтернативой |
| C3 | Временные метки обязательны | См. §D |
| C4 | Деньги — только целые числа в минорных единицах (тыйын, 1/100 сома) | `float` недопустим ни в БД (`integer`/`bigint`), ни в TS |
| C5 | Время — `timestamptz` в БД, ISO-8601 UTC в API, unix ms в WS-сообщениях | Единый формат, нет «локального времени в БД» |
| C6 | Фронт не знает про HTTP: только через `ApiClient` (интерфейс) | Мок-реализация и реальная реализация взаимозаменяемы, UI тестируем без сервера |
| C7 | Компоненты не ходят в сеть и не знают про транспорт данных | Тестируемость, отсутствие дублирования логики загрузки |
| C8 | Каждая стадия закрывается тестами и записью в `docs/evidence/` | Требование A13 |
| C9 | Коммиты — на английском, Conventional Commits, атомарно по стадии | Правило пользователя |
| C10 | Никаких `.gitkeep` и файлов-заглушек «на будущее» | Стиль пользователя |
| C11 | Сервер — источник истины по времени и деньгам; клиентское время только для отображения (drift-офсет) | B4, B7 |
| C12 | Тесты: `vitest` (front + back + shared), `@testing-library/react` (компоненты), `app.inject()` (ручки), e2e — Playwright с `channel: msedge` (без скачивания Chromium) | Быстро, без 700 МБ загрузок |
| C13 | Порты по умолчанию: frontend 5173 (dev) / 8088 (docker), backend 3000, Postgres 5434 (5433 занят другим проектом) | Избежать конфликтов с существующими локальными стеками |

## D. Временные метки (явное требование «добавить временные метки»)

1. **БД**: на каждой таблице `created_at timestamptz NOT NULL DEFAULT now()`, `updated_at timestamptz NOT NULL DEFAULT now()` + триггер `set_updated_at()` на `UPDATE`. Таблицы без `updated_at` только append-only (телеметрия, события, письма).
2. **Домен**: `reserved_at`, `expires_at`, `started_at`, `finished_at`, `paused_at`; интервалы пауз — отдельные строки `(started_at, ended_at)`; телеметрия — `recorded_at`.
3. **API**: каждый ответ с состоянием/поездкой содержит `server_time` (ISO UTC). Клиент считает оставшееся время брони от `server_time`, не от локальных часов.
4. **WS**: у каждого сообщения `seq` (монотонный счётчик) и `sent_at`; после реконнекта клиент запрашивает снапшот и сравнивает `seq`, чтобы не применить устаревшее сообщение.
5. **Фронт**: единый `useServerClock()` хранит `offset = server_time - Date.now()` и отдаёт «серверное сейчас»; прямые `Date.now()` в расчётах таймеров запрещены (кроме тестов).
6. **Тесты**: у каждой проверки таймингов — инъекция часов (`Clock` с `now()`), реальные таймеры в тестах не ждём; отдельный тест на дрейф `server_time` ±30 с.
