«Правки не видны»: старая сборка в браузере + расхождение минут. Дата: 14.10.2026.

Разбор жалобы: «в поездках 13:18, 2 мин; в счёте 13:20, Езда 3 мин». Это две разные вещи, и обе
исправлены.

1. Минуты считали по-разному (исправлено ранее, подтверждено здесь).
   Поездка 07:18:26 → 07:20:53 UTC (13:18 → 13:20 местного), длительность 2 мин 27 с.
   Домен тарифицирует начатые минуты сегмента: 3 минуты → 3 × 6.00 = 18.00 + посадка 25.00 = 43.00,
   что и стоит в счёте. История показывала округление длительности (Math.round) → «2 мин».
   Теперь минуты в историю отдаёт сервер, посчитанные тем же доменом:
   `2026-10-14T07:18:26.185Z  rideMinutes=3  pauseMinutes=0  totalAmount=4300` (ответ /api/rides).

2. Почему правки вообще не доходили до браузера.
   В nginx не было заголовка для index.html: файл отдавался без Cache-Control, а он — единственный,
   кто ссылается на сборку с хешем в имени. Браузер применял эвристическое кэширование и держал
   старый index.html со старым бандлом: перезагрузка страницы не помогала (именно так выглядела
   повторная жалоба).
   Добавлено:
     location = /index.html { add_header Cache-Control "no-cache, must-revalidate"; }
   Проверка заголовков:
     /              → Cache-Control: no-cache, must-revalidate
     /index.html    → Cache-Control: no-cache, must-revalidate
     /assets/*.js   → Cache-Control: public, immutable (max-age=2592000) — имена с хешем, можно долго

Фактический вид после сброса кэша (живой стенд, браузер, страница «Поездки»):
  14 октября в 13:18 | до 13:20 | Езда 3 мин · пауза 0 мин | Завершена вами | 43.00 сом
Страница «Счета» для той же поездки:
  Счёт от 14 октября в 13:20 | 43.00 сом | Посадка 25.00 | Езда · 3 мин 18.00 | Пауза · 0 мин 0.00

Числа совпадают, время подписано: в истории — период поездки, в счёте — момент выставления.
