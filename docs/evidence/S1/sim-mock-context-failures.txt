------------------------------------------------------------------------------
1) Что произошло

Воркер S1-sim (deleg_0807b23b, 1120 с) упал:
  status=failed api_calls=18 duration=1120.57s
  error: "The model server rejected this request as too large, but this conversation is only about
          88,755 tokens — well under the 262,144-token window Hermes knows for kat-coder..."

Воркер S2-mock (deleg_e777f322) встал по той же причине: транскрипт перестал расти
(последняя запись 20:34:48, проверка в 20:39 — 4 с лишним минуты тишины), остановлен оркестратором.

------------------------------------------------------------------------------
2) Причина

llama-server был запущен с `-c 262144` без `-np`, то есть с 4 слотами:
  лог старта: "initializing, n_slots = 4, n_ctx_slot = 262144", /slots показывал 4 слота.
На практике воркеры получали по ~64-65k на слот: промпт воркера дорос до 88 755 токенов
(он собирает контекст из итераций: чтение файлов, патчи, выводы тестов) — сервер отверг запрос.

Замечание: сами задания требуют читать минимум файлов, но контекст растёт от итераций,
а не только от чтения. Воркер S1-sim сделал 18 api-вызовов, S2-mock — 30+.

------------------------------------------------------------------------------
3) Что сделано

Профиль сервера изменён: `-np 2` (по 131 072 токена на слот) + лог в файл с таймстампами:
  ./llama-server.exe ... -c 262144 -np 2 ... --log-file E:/llama.cpp/llama-server.log --log-timestamps

Проверено после перезапуска:
  $ curl -s localhost:8080/slots
  slots: 2
   id 0 n_ctx 131072
   id 1 n_ctx 131072
  $ npm run ram:check   (E:\llama.cpp\ram-guard.ps1)
  physical : 31,9 GB total, 8,3 GB free (74,1% used)      <- было 3,0 GB free
  commit   : 45,1 GB limit, 34,1 GB used (75,6%)           <- было 89,1%
  llama-server: private 20,12 GB, working set 15,76 GB     <- было private 27,78 GB

Побочный эффект оказался важнее основного: два слота вместо четырёх освободили ~7,7 ГБ commit.
Причина — под каждый слот llama.cpp резервирует host-буферы и workspace, и они не разделяются.

Профиль зафиксирован в E:\llama.cpp\start-kat.cmd (добавлен `-np 2` и комментарий с замерами),
чтобы следующая сессия не наступила на те же грабли.
