# DECISIONS.md — лог решений (ADR)

Формат: `ADR-NNN · решение` → контекст, выбор, альтернативы и почему отклонены, последствия.
Требование ТЗ: «промпты или лог решений сдаются вместе с кодом». Этот файл — тот самый лог.

---

## ADR-001 · Frontend: React 19 + Vite 8 + TypeScript

**Контекст.** ТЗ допускает Vue или React. Фронт плотно работает с картой, таймерами и WS.
**Решение.** React + Vite + TS, SPA.
**Альтернативы.** Vue 3 + Vite — равноценен технически, отклонён: экосистема shadcn/ui и
react-leaflet даёт готовые примитивы, а тайпинг карты (leaflet) проверен.
**Последствия.** Vite 8 требует Node ≥ 20.19 — фиксируем Node 22 LTS.

## ADR-002 · Backend: Node.js 22 + TypeScript + Fastify 5

**Контекст.** ТЗ: Python/Go/Node, предпочтительно из списка.
**Решение.** Node + TS + Fastify. Причина №1 — общий `shared`-контракт (типы + zod-схемы) для фронта
и бэка: одна доменная модель вместо двух синхронизируемых вручную. Причина №2 — реалтайм (ws-хаб +
тик симулятора) в одном процессе без отдельного рантайма. Причина №3 — один базовый образ `node:22-alpine`.
**Альтернативы.** FastAPI (Python) — пришлось бы дублировать типы контракта и держать второй toolchain;
Go — лаконичнее по рантайму, но больше шаблонного кода для 15 ручек, выигрыша здесь нет.
**Последствия.** Отклонён NestJS: DI-контейнер и декораторы избыточны для 15 ручек (рулсет C1, C2).

## ADR-003 · Хранилище: PostgreSQL 17, доступ через `pg`, без ORM/Prisma

**Контекст.** ТЗ: реляционная СУБД, предпочтительно PostgreSQL. Проект локальный.
**Решение.** `postgres:17-alpine` + `pg` (Pool) + собственные SQL-миграции.
**Альтернативы.** Prisma — запрещён рулсетом (тяжёлая генерация, свой рантайм, миграции «в чёрном ящике»);
Kysely — типобезопасный SQL-builder, но вводит второй язык описания схемы. При гонках за самокат нужен
предикативный `UPDATE ... WHERE status='free'`, который на чистом SQL читается однозначно.
**Последствия.** Схема описывается вручную (миграции + CHECK/индексы), это компенсируется тестами на инварианты БД.

## ADR-004 · Реалтайм: WebSocket (`ws`) + снапшот/дельта с монотонным `seq`

**Контекст.** Требования B1 (состояние у всех сразу), B2 (мгновенный отказ второму), B7 (потеря связи).
**Решение.** Один ws-эндпоинт `/ws`: снапшот при подключении, дальше дельты парка; каждое сообщение
несёт `seq` и `sent_at`. `@fastify/websocket` + `ws`.
**Альтернативы.** SSE — только сервер→клиент, для «отказ приходит мгновенно» хватает HTTP-ответа,
но нет heartbeat-семантики и единого канала состояния; HTTP-поллинг 2 с — не выполняет «сразу»
и грузит сервер. Socket.IO — лишний протокол и вес.
**Последствия.** Нужна логика реконнекта и отбрасывания устаревших сообщений по `seq` (покрываем тестом).

## ADR-005 · Мок-данные: JSON-файлы в `mock/` + `MockApiClient`, не MSW

**Контекст.** Стадийность: сначала фронт целиком на моках, сервер позже. Решение пользователя (2026-10-13):
«псевдо-запросы к локальному json, засидить через локальную модель».
**Решение.** `mock/*.json` — общий источник: фронт фетчит те же файлы как статику Vite,
бэкенд на стадии S8 сидирует из них БД. Доступ через `ApiClient`-интерфейс с двумя реализациями.
**Альтернативы.** MSW — перехват на уровне сети выглядит реалистичнее, но добавляет service-worker
и усложняет отладку (не видно, что данные мок, в devtools не отличить от реальных); отдельный
mock-сервер — третий процесс и фронт без него не живёт.
**Последствия.** Контракт API фиксируется типами (S1) до появления сервера; риск расхождения
снимается тем, что zod-схемы — общие.

## ADR-006 · Состояние фронта: zustand (+ react-router 7), без TanStack Query

**Контекст.** Нужны: поток парка по ws, своя бронь/поездка, счета, история.
**Решение.** `zustand` для клиентского состояния и кэша серверных данных; запросы — через `ApiClient`
в экшенах стора. Роутинг — `react-router 7`.
**Альтернативы.** TanStack Query — мощный, но при живом ws-потоке большая часть инвалидации избыточна,
а проект локальный (рулсет C1: минимум зависимостей).
**Последствия.** Логика «загрузить/обновить» пишется руками — но она тонкая (список парка, активная
поездка) и покрывается тестами стора.

## ADR-007 · Карта: Leaflet + react-leaflet 5, подложка ArcGIS Light Gray Canvas

**Контекст.** Нужны маркеры, полигон зоны, попапы; ключей API нет и не хочется.
**Решение.** Leaflet (raster XYZ) + `World_Light_Gray_Base` с `server.arcgisonline.com` (проверено:
тайлы реальные, не заглушка «API key required»), maxZoom 16. Атрибуция Esri обязательна.
**Альтернативы.** OSM-тайлы — по политике не для встраивания (403 при чужом Referer);
CARTO/MapTiler/Stadia — требуют ключ; MapLibre + вектора — лишний слой для растровых задач.
**Последствия.** Провайдеры — реестром в `config/`, смена подложки = одна строка.

## ADR-008 · Деньги: целые минорные единицы (тыйын), поминутное округление вверх по интервалам

**Контекст.** Требование B4 («счёт по минутам… копейки не теряются»).
**Решение.** Хранение и расчёт — `bigint`/`number` в тыйынах; каждый интервал езды и каждая пауза
округляется вверх до полной минуты раздельно (`DOMAIN.md §5`).
**Альтернативы.** `numeric(12,2)` — корректно, но требует аккуратности с `pg` (строки) и не защищает
от `float` в TS; посекундная тарификация с точностью до тыйына — даёт «странные» копейки в счёте
и расходится с «по минутам» в ТЗ.
**Последствия.** Округление каждого интервала вверх осознанно консервативно для пользователя,
эталонные примеры зафиксированы тестами (`DOMAIN.md §5`).

## ADR-009 · Вход: email + пароль, JWT access (память) + refresh (httpOnly cookie)

**Контекст.** ТЗ A5 — модель входа на наше усмотрение.
**Решение.** bcryptjs (чистый JS — нет нативной сборки в alpine-образе), JWT 15 мин + refresh-cookie 7 дней.
**Альтернативы.** argon2 — лучше по стойкости, требует нативной сборки (`node-gyp`, python/make)
в контейнере; сессии в БД — плюс таблица и хранилище, для локального проекта избыточно.
**Последствия.** Гость видит карту без входа; бронь и поездка требуют авторизации.

## ADR-010 · Тесты: vitest везде, `app.inject()` вместо supertest, Playwright с `channel: msedge`

**Контекст.** Rулсет C8/C12, требование доказуемости (A13).
**Решение.** vitest в `shared`/`frontend`/`backend`, `@testing-library/react` для компонентов,
встроенный `app.inject()` Fastify для ручек (без сетевого порта и без supertest), Playwright для e2e —
с системным Edge, чтобы не тянуть Chromium (~700 МБ) в локальную машину.
**Альтернативы.** Jest — медленнее и требует отдельной настройки ESM/TS; Cypress — тяжёлый рантайм.
**Последствия.** e2e требует установленного Edge (есть на Windows 11 по умолчанию), это описано в RUNBOOK.

## ADR-011 · Docker: три контейнера, фронт-nginx проксирует `/api` и `/ws`

**Контекст.** ТЗ A1/A9/A11: отдельные клиент и сервер, общаются по сети, разворачивается локально.
**Решение.** compose с `frontend` (nginx:alpine, сборка Vite), `backend` (node:22-alpine), `db`
(postgres:17-alpine, том, healthcheck). Наружу — только фронт (8088) и БД (5434); бэкенд доступен
фронту по внутренней сети `app_net`; nginx проксирует `/api` и `/ws` (включая `Upgrade`).
**Альтернативы.** Отдельный контейнер-прокси (traefik) — третий лишний процесс; публиковать бэкенд
наружу и решать CORS — лишняя конфигурация и открытый порт.
**Последствия.** Порты 5434 и 8088 выбраны вне диапазона других локальных проектов на машине (5433 занят).

## ADR-012 · Симулятор транспорта: серверный тик 1 с, на фронт-стадии — тот же алгоритм в браузере

**Контекст.** Требование «транспорт с GPS и уровнем заряда — симулятор, входит в задание».
**Решение.** Алгоритм — чистый модуль в `shared/src/sim/` (шаг позиции, расход заряда, события).
На стадии S2–S7 его крутит фронт (`lib/simulator`, интервал 1 с), на S9 — бэкенд; код общий.
**Альтернативы.** Два независимых симулятора — гарантированное расхождение поведения моков и сервера.
**Последствия.** Симулятор обязан быть детерминированным при заданном seed — иначе тесты флакуют.

## ADR-013 · Часы: инъекция `Clock`, серверное время как источник истины

**Контекст.** Таймер брони 15 мин, поминутная тарификация, потеря связи, два клиента с разными часами.
**Решение.** `Clock` с `now()` прокидывается в сервисы и в UI; тесты используют ручные часы.
Каждый ответ API и ws-сообщение несёт `server_time`; фронт держит `useServerClock()` с drift-офсетом.
**Альтернативы.** `Date.now()` напрямую — тесты таймеров становятся медленными и флакующими.
**Последствия.** Запрет `Date.now()` в расчётах (рулсет C11), покрыт линт-правилом/ревью.
