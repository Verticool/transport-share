# ACCEPTANCE.md — доказуемость (требование ТЗ №13)

Каждый пункт ТЗ получает: **как проверяем**, **чем** (команда), **что видим** (сырой вывод в `docs/evidence/`).
Строка без сырого вывода считается непроверенной. Заполняется по мере закрытия стадий.

Обозначения: `[ ]` — не проверено, `[x]` — проверено, ссылка на evidence.

| # | Требование | Проверка | Инструмент | Evidence |
|---|---|---|---|---|

| B4 | Поминутная тарификация, пауза отдельно, копейки не теряются | таблица цен `DOMAIN.md §5` дословно | vitest (таблица) | [ ] |

## C. Как выглядит приёмка (процедура)

1. Прогон `npm run check` (typecheck/lint/unit/integration) — вывод в `docs/evidence/S<стадия>/check.txt`.
2. Прогон `npm run test:e2e` — вывод и скриншоты в тот же каталог.
3. Ручной замер в браузере оркестратором (геометрия, состояния, визуальная оценка по скриншоту) —
   результат текстом + скриншот.
4. `docker compose ps` и `curl /api/health` — сырой вывод.
5. Обновление этого файла и `STATUS.md`; всё, что не проверено, остаётся `[ ]` со словом о причине.
