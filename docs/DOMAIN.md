# DOMAIN.md — доменная модель, статусы, тарифы, тайминги

Референс для всех: и фронт, и бэкенд, и мок-данные используют эти определения дословно.

## 1. Сущности

**Scooter (самокат)** — единица парка.
`id`, `code` (человекочитаемый, `SC-001`), `model`, `status`, `battery_pct` (0–100, целое),
`lat`, `lng`, `last_seen_at`, `created_at`, `updated_at`.

**User** — `id`, `email`, `name`, `password_hash`, timestamps.

**Booking (бронь)** — удержание самоката за пользователем до старта.
`id`, `user_id`, `scooter_id`, `status`, `reserved_at`, `expires_at`, `notified_at`, `closed_at`, timestamps.

**Ride (поездка)** — `id`, `user_id`, `scooter_id`, `booking_id`, `status`,
`started_at`, `finished_at`, `end_reason`, `distance_m`, `total_amount`, `currency`, timestamps.

**RidePause** — интервал паузы: `ride_id`, `started_at`, `ended_at`.

**Invoice (счёт)** — `ride_id` (unique), `amount`, `currency`, `breakdown` (jsonb), `issued_at`.

**Email (эмуляция почты)** — `to_email`, `subject`, `body`, `dedupe_key` (unique), `sent_at`.

**RidePoint / RideEvent** — append-only телеметрия и события с `recorded_at`.

## 2. Статусы и переходы

### Самокат
```
              ┌─────────────────────────── заряд < 20 % ───────────────┐
              │                                                        ▼
  free ──бронь──▶ reserved ──старт──▶ in_ride ──финиш──▶ free    unavailable
    ▲                │                    │                 ▲              │
    │                │ истечение 15 мин   │ отмена          │              │ заряд ≥ 20 %
    │                │ / отмена           │                 │              │ (обслуживание)
    └────────────────┴────────────────────┘                 └──────────────┘
```
Правила:
- `free` — доступен для брони; показывается свободным, только если `battery_pct >= 20`.
- `reserved` — удерживается за одним пользователем до `expires_at`.
- `in_ride` — поездка идёт (включая паузу: пауза — состояние поездки, не самоката).
- `unavailable` — низкий заряд или обслуживание; бронировать нельзя, на карте отображается серым.
- Переходы делает только сервер (на фронт-стадии — мок-симулятор по тем же правилам).

### Бронь
`active` → `consumed` (начали поездку) | `expired` (не начали за 15 мин) | `cancelled` (отменил сам).

### Поездка
`active` ⇄ `paused` → `finished`. `end_reason ∈ {user, battery_depleted, service}`.

## 3. Тайминги (все — серверные, `timestamptz`)

| Событие | Значение |
|---|---|
| Бронь живёт | `expires_at = reserved_at + 15 мин` |
| Напоминание | за 3 мин до `expires_at`, ровно один раз (`notified_at` не NULL) |
| Тик контроля брони | 5 с |
| Тик симулятора парка | 1 с |
| Длительность паузы | без ограничения по времени, тарифицируется отдельно |
| Минимальная единица тарификации | секунда, округление до полной минуты вверх, по каждому интервалу |
| Клиентское время | только отображение; все расчёты — от `server_time` |

## 4. Тарифы (сом, KGS)

| Позиция | Значение | Хранение |
|---|---|---|
| Разблокировка | 25.00 сом | `2500` тыйын |
| Езда | 6.00 сом/мин | `600` тыйын/мин |
| Пауза | 2.00 сом/мин | `200` тыйын/мин |

Деньги — всегда целое число минорных единиц (тыйын, 1 сом = 100 тыйын). Суммы в БД — `bigint`.

## 5. Формула цены (эталон для тестов)

```
segments = интервалы между паузами внутри [started_at, finished_at]
ride_minutes   = Σ ceil(секунды(seg) / 60)
pause_minutes  = Σ ceil(секунды(pause) / 60)
total = 2500 + ride_minutes * 600 + pause_minutes * 200   (тыйын)
```
Эталонные примеры (обязаны пройти тестом):

| Сценарий | Езда | Пауза | Итого |
|---|---|---|---|
| 0 с (старт и сразу финиш) | 1 мин | 0 | 2500 + 600 = **3100** (31.00 сом) |
| 59 с | 1 мин | 0 | **3100** (31.00 сом) |
| 60 с | 1 мин | 0 | **3100** (31.00 сом) |
| 61 с | 2 мин | 0 | **3700** (37.00 сом) |
| 15 мин ровно | 15 мин | 0 | 2500 + 9000 = **11500** (115.00 сом) |
| 10 мин + пауза 4:20 + 5 мин | 15 мин | 5 мин | 2500 + 9000 + 1000 = **12500** (125.00 сом) |
| пауза 30 с | 0 мин | 1 мин | 2500 + 200 = **2700** (27.00 сом) |

Замечания:
- Поездка «0 секунд» тарифицируется как 1 минута езды: таймер стартует и к моменту финиша уже
  начата первая минута. Это ожидаемое поведение, а не баг (фиксируется тестом).
- Разблокировка списывается один раз на поездку, не на бронь.
- Отменённая бронь и истечение брони — **бесплатны** (никаких списаний).
- Финиш вне зоны обслуживания отклоняется (`422`), поездка продолжается, деньги не списываются.

## 6. Зона обслуживания

Полигон (порядок точек против часовой, координаты — WGS84) вокруг центра Бишкека:
```
42.8900, 74.5450   42.8990, 74.5900   42.8850, 74.6300   42.8500, 74.6350
42.8290, 74.6100   42.8200, 74.5650   42.8350, 74.5300   42.8650, 74.5250
```
Правила:
- Бронь и старт — только внутри зоны (самокат вне зоны не показывается свободным).
- Завершение поездки — строго внутри полигона; иначе `422 outside_zone` и понятное сообщение в UI.
- При приближении к границе (< 150 м) — предупреждение в UI; граница всегда нарисована на карте.
- Проверка — ray casting по полигону в `shared/src/zone.ts`, без PostGIS.

## 7. Поведенческие сценарии (каждый = тест)

1. **Двое жмут «Забронировать» один самокат одновременно.** Побеждает ровно один; второй получает
   `409 scooter_not_free` и видит самокат уже `reserved` (B2).
2. **Бронь без старта.** 12-я минута → уведомление «осталось 3 минуты» (in-app + письмо);
   15-я минута → бронь `expired`, самокат `free` (B3).
3. **Поезда с паузой.** Пауза не считается ездой, тарифицируется отдельно, интервалы не склеиваются (B4).
4. **Пауза.** Пауза — это выключенный мотор: самокат стоит на месте, заряд не расходуется, руль
   не действует. Время паузы тарифицируется по отдельному тарифу (B4).
5. **Финиш вне зоны.** За границей зоны обслуживания мотор работает (самокат едет — человек может
   вернуться своим ходом), но завершить поездку нельзя: отказ 422, кнопка «Завершить» неактивна,
   причина написана рядом. Поездка не закрыта, время продолжает тарифицироваться. Вернуться можно
   рулём (см. ниже) или действием «вернуть самокат в зону» (`POST /api/rides/:id/push-to-zone`),
   после чего поездка завершается обычным порядком (B11, B22).
6. **Заряд 0 % во время поездки.** Автофиниш, `end_reason='battery_depleted'`, письмо со
   счётом и пояснением «самокат разрядился, поездка завершена автоматически» (B6).
7. **Потеря связи.** Клиент офлайн 3 минуты, затем возвращается: поездка всё это время шла,
   счёт вырос, состояние карты и брони — актуальное (B7).
7. **Завершение поездки.** Ровно одно письмо со счётом; повторный `finish` → тот же счёт, не новый (B8).
8. **Низкий заряд.** Самокат с 12 % не показывается свободным и не бронируется (B9).
9. **Две вкладки.** Состояние карты в обеих меняется сразу после любой брони/старта/финиша (B1, A11).

## 8. Роли и вход

- Гость: карта, зона, статусы парка (read-only), легенда.
- Пользователь: всё выше + бронь, поездка, кабинет, счета, входящие.
- Пароль: bcryptjs, минимум 8 символов. JWT: access 15 мин (память), refresh 7 дней (httpOnly cookie).
- Вторая поездка при активной первой — запрещена (`409 ride_already_active`).
